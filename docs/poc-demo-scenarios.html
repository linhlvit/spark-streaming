CDC Sync — INSERT mới

📝
INSERT vào T24_TRANSACTIONS
Nguồn Oracle T24
→
🔍
Debezium capture
op=c, after.* payload
→
🌊
Kafka topic
oracle.FSS_STREAM.T24_TRANSACTIONS
→
✅
T24_TRANSACTIONS_TARGET
MERGE ON TRANSACTION_ID
# Giả lập: tạo giao dịch với TRANSACTION_ID ngẫu nhiên
python3 tools/test_pipeline.py --scenario sync

Kiểm tra kết quả

✅
Row xuất hiện trong T24_TRANSACTIONS_TARGET trong ≤ 30s
✅
AMOUNT, BRANCH_CODE khớp với INSERT nguồn
✅
Chạy lại → không duplicate (MERGE idempotent)

SQL xác nhận

SELECT TRANSACTION_ID, AMOUNT,
  BRANCH_CODE

WHERE TRANSACTION_ID = :id;
S2 · Pattern 1

CDC Sync — UPDATE last-write-wins

✏️
INSERT → rồi UPDATE
TRANSACTION_STATUS: PENDING → COMPLETED
→
📦
Debezium 2 events
op=c rồi op=u (before+after)
→
🛡️
LWW Guard
UPDATE WHERE t.TRANSACTION_TIME < s.TRANSACTION_TIME
→
✅
TARGET = COMPLETED
Event mới nhất thắng
python3 tools/test_pipeline.py --scenario sync_update

Kiểm tra kết quả

✅
TRANSACTION_STATUS = 'COMPLETED' trong TARGET
✅
Nếu 2 event đến out-of-order, event cũ không ghi đè
✅
AMOUNT không thay đổi (chỉ STATUS update)

Out-of-order test (thêm)

Gửi event cũ sau event mới → kiểm tra TARGET vẫn giữ giá trị mới.
Guard: WHERE t.ts < s.ts trong MERGE.

Latency mong đợi

Từ Oracle INSERT → T24_TXN_ENRICHED: ≤ 30s
Bao gồm: Debezium lag (~2s) + Kafka lag (~1s) + Spark micro-batch (~10s) + Oracle MERGE (~1s)

↓
foreachBatch: join miss
ERROR_CODE = BRANCH_NOT_FOUND
↓

S6: DLQ RETRY → RESOLVED

↓
reset NEXT_RETRY_AT = now
Trigger retry ngay
↓
retry_txn_branch_dlq.py --once
STATUS = RESOLVED + ENRICHED ghi

  --scenario dlq_retry

Aggregation — Tích lũy & Revert

↓
TOTAL_AMOUNT -= 5M (revert delta)
