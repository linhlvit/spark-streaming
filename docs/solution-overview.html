Pattern áp dụng chung

⚡
foreachBatch Sink
Ghi Oracle per micro-batch. Idempotent qua Spark checkpoint — không replay cùng batch_id 2 lần.
🔄
Oracle MERGE (UPSERT)
MERGE ... ON (PK). An toàn khi batch replay. Named bind variables tránh SQL injection.
🔌
oracledb thuần (thin)
Không dùng spark.read.jdbc. Lý do: ClassCastException khi dùng JDBC driver trong foreachBatch executor.
⏱️
Last-write-wins Guard
MERGE WHEN MATCHED UPDATE WHERE t.event_ts < s.event_ts — ngăn event cũ ghi đè event mới khi out-of-order.

Static Join · Quyết định

Tại sao flat schema cho DLQ?

❌ CLOB JSON

Retry cần deserialize JSON để lấy BRANCH_CODE
Khó query trực tiếp bằng SQL khi debug
Không thể đặt index hay alert theo field
Phù hợp khi schema thay đổi thường xuyên

✅ Flat Schema

BRANCH_CODE truy cập trực tiếp, không cần parse
Dễ query, alert, debug bằng SQL thuần
Index được trên BRANCH_CODE để group retry
Schema T24_TRANSACTIONS ổn định — không cần generic
Exponential backoff: static_join 5→15→60→240→1440 phút | stream_join 10→30→120→360→1440 phút — NEXT_RETRY_AT trong Oracle, không dùng sleep thread

📊 Pattern 4

Stateful Aggregation — Doanh số chi nhánh

LUỒNG XỬ LÝ
op=c (INSERT): SIGNED = +AMOUNT
op=u (REVERT): SIGNED = −before.AMOUNT
groupBy BRANCH_CODE, RPT_DATE, CURRENCY_CODE
MERGE += DELTA (cộng dồn, không tính lại)
IDEMPOTENCY
T24_STREAM_BATCH_LOG ghi batch_id đã xử lý
Cùng Oracle transaction với MERGE delta
Spark replay batch_id cũ → skip, không double-count
Cleanup log > 7 ngày sau mỗi batch commit
Output: T24_BRANCH_SALES_SUMMARY(BRANCH_CODE, RPT_DATE, CURRENCY_CODE, TOTAL_AMOUNT, TXN_COUNT) — PK composite, latency ~35–70s
⚡ Out-of-order CDC

Xử lý sự kiện lệch thứ tự

NGUỒN GỐC
Debezium restart đọc lại từ earliest
Kafka multi-partition: consumer lag không đều
Oracle RAC: LogMiner từ nhiều node
Spark executor restart — batch replay
GIẢI PHÁP
CDC Sync: last-write-wins guard trong MERGE
WHERE t.event_ts < s.event_ts
Aggregation: revert semantics từ before.AMOUNT
op=u → SIGNED = −before.AMOUNT
Không ảnh hưởng: Stream-Stream Join dùng watermark ±30min để tự lọc event quá cũ. Static Join reload branch mỗi batch nên luôn có data mới nhất.
⚠️ DLQ Design

Tại sao không dùng daemon thread?

❌ Tài nguyên Daemon thread chiếm executor Spark — cạnh tranh với streaming job chính
❌ Checkpoint Không được Spark checkpoint quản lý — mất trạng thái khi executor restart
❌ Độc lập Không thể restart riêng lẻ — phải restart cả streaming job
❌ Quan sát Không có log/metric riêng — khó debug, không thể alert theo DLQ rate
❌ Scheduling Không thể lên lịch linh hoạt (exponential backoff, peak-hour throttle)

Nguồn: Uber Engineering — "Building Reliable Reprocessing and Dead Letter Queues" (Ning Xia, 2018)
